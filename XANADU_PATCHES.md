# Xanadu patches

This branch is an upstream fdtdx release ([ymahlau/fdtdx](https://github.com/ymahlau/fdtdx)) plus the short series
of Xanadu commits below, which SilverHammer needs inside fdtdx itself. Everything else Xanadu-specific (subpixel
averaging, mode caching, dtype choices, buffer donation, plotting, S3) lives in SilverHammer.

- **Branch naming:** `xanadu/<upstream tag>`, for example `xanadu/v0.6.3` is `v0.6.3` plus the patches below.
- **Syncing:** a sync replays the series onto the next upstream tag as a new branch. Existing branches are never
  rewritten, so commit pins in SilverHammer keep working.
- **Markers:** every edit inside an upstream file carries a `XANADU:` comment (or, for the dtype pins, uses the
  `material_dtype` name), so conflicts are quick to find.
- **Tests:** Xanadu tests live in `tests/**/xanadu/`. The upstream suite (`-m "unit or integration"`) must stay green.

| # | Patch | Why | Files | Tests |
|---|---|---|---|---|
| 1 | Precomputed materials in `place_objects` | SilverHammer builds the whole volume's materials itself, subpixel averaging included. fdtdx uses `precomputed_inv_permittivities` / `precomputed_electric_conductivity` as given (no second full-grid array, no rescaling) and solves sources against them. It refuses fdtdx subpixel smoothing (which would average twice), other material objects (which would be ignored) and dispersive materials. | `src/fdtdx/fdtd/initialization.py` | `tests/integration/xanadu/test_precomputed_materials.py` |
| 2 | Mixed precision: `SimulationConfig.material_dtype` | SilverHammer runs under jax x64 with float64 fields, PML, sources, mode solves and detectors, and float32 full-grid material arrays (permittivity, permeability, conductivity) for half the memory. `material_dtype` defaults to `dtype`, so upstream behavior is unchanged unless it is set. Precomputed arrays must match it. Also fixes upstream's PML `sigma_end`, which became a strongly typed float64 under x64 and broke float32 runs. | `src/fdtdx/config.py`, `src/fdtdx/fdtd/initialization.py`, `src/fdtdx/objects/boundaries/perfectly_matched_layer.py` | `tests/integration/xanadu/test_mixed_precision.py` |
| 3 | TFSF injections cast to the field dtype | A lossy mode source is complex128 under x64 even in a float32 run. Its face injections were added straight into E/H, which made a full-grid float64 copy of the field for every add (JAX warns this will become an error). The plane-sized increment is now cast to the field's own dtype, as `source.py` and `dipole.py` already do. Float64 runs are unchanged. | `src/fdtdx/objects/sources/tfsf.py` | `tests/integration/xanadu/test_mixed_precision.py` (`test_float32_run_stays_float32_under_x64`) |
| 4 | Delta-form lossy E/H updates | Upstream's `((1 - half) * E + K) / (1 + half)` forms `1 - half` from the float32 materials, which rounds to exactly 1 for weak losses (`half` below ~6e-8), so they vanish even with float64 fields. The update is now `E + (K - 2 * half * E) / (1 + half)` (algebraically identical, ADE term included in `K`), with `half` cast to the field's real dtype so the reverse updates stay exact inverses. Isotropic/diagonal branches of `update_E`, `update_E_reverse`, `update_H`, `update_H_reverse`; the 9-component tensor path is untouched. | `src/fdtdx/fdtd/update.py` | `tests/integration/xanadu/test_delta_form_updates.py` |
| 5 | Mode-solve reuse and the polarization-count check | SilverHammer needs every mode index in both directions on each monitor plane. `compute_mode` takes `num_modes` (default: upstream's `2 * (mode_index + 1) + 10`); with the same value for every call on a plane, the forward tidy3d solve (backward modes are derived from it) is reused, since the last solve is kept. Results are identical to solving each time. A `filter_pol` index past the modes of that polarization raises instead of returning the other polarization. The one solve call is also the place to swap in another mode solver later. | `src/fdtdx/core/physics/modes.py` | `tests/integration/xanadu/test_mode_solve_reuse.py` |
| 6 | Detector co-location along the normal only (`Detector.normal_axis_interpolation`) | Upstream co-locates every component onto the E_z point, averaging across the plane too, which smears fields across waveguide walls and destabilizes ports of different shapes (on bent_dc it moved converged port amplitudes by up to 5%). With the opt-in flag, only the components half a cell off the plane (normal E, tangential H) are averaged, along the normal, and every component keeps its transverse Yee position, the one the mode solver uses. Bit-identical to the fork's 02c6492; at the domain edge the cell below comes from the boundary padding. Not supported with `config.symmetry`. Re-port at the next sync: upstream main #461 moves detector co-location into `colocate_detector_fields`. | `src/fdtdx/objects/detectors/detector.py`, `src/fdtdx/core/physics/curl.py`, `src/fdtdx/fdtd/update.py` | `tests/integration/xanadu/test_normal_axis_interpolation.py` |
